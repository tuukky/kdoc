## 1. 목표와 범위

목표: **"공고가 올라오면 사람이 손대지 않아도 검토 결과가 알림으로 오는" 운영 흐름**을 n8n으로 만들고, 실제로 2주 돌려 운영 수치를 남긴다.

| ID | 워크플로 | 트리거 | 하는 일 |
|---|---|---|---|

### 역할 나누기 원칙

- **n8n**: 언제·무엇을·어떤 순서로·실패하면 어떻게 (트리거, 외부 API 호출, 필터, 분기, 재시도, 알림, 폼).
- **kdoc-api**: 문서 처리와 기록 (첨부 분류, 다운로드, 추출·비교, 판정 집계, 운영 로그 DB). 로직은 pytest로 검증할 수 있는 곳에 둔다.
- **알림 = 화면 알림함**: n8n이 `POST /alerts`로 알림을 남기고, kdoc-api가 제공하는 알림함 화면(`http://127.0.0.1:8000/ui/alerts`)에 쌓인다. 메신저·메일 연동은 하지 않는다 (필요해지면 n8n에 노드 하나만 추가).
- 비밀값(W5의 OpenAI 키)은 **n8n 자격 증명(credential)** 에만 저장한다. 워크플로 JSON·저장소에 남기지 않는다. 공고 수집에는 키가 필요 없다 (§8).

## 4. 규칙 (사전 등록)

### 4.1 W1 공고 필터

- 대상: 나라장터 **공사** 입찰공고 (`prcmBsneAreaCd=조070004`, 용역·물품 제외), 게시일 기준 전날 ~ 당일.
- 검색 키워드(공고명): `화장실, 방수, 외벽, 도장, 타일, 창호, 단열, 리모델링`. (`보수`·`개선`은 한 주 300건 넘게 걸리고 건축과 무관한 공고가 많아 제외 — 2026-11-11 건수만 보고 결정, 검토 결과는 보지 않음)
- 제외: 공고명에 `전기·통신·소방·기계설비·조경·토목·포장` **공사**가 붙은 경우 (정규식 `(전기|통신|소방|기계설비|조경|토목|포장)\s*공사`, 예: "화장실 설치 전기공사"). 2026-11-11 W1 구현 때 처음 문구("위 단어가 없는 경우")가 키워드 검색 결과에는 적용될 일이 없어 고침 — W1 첫 실행 전, 검토 결과를 보기 전.
- 추정가격 10억 원 이하 (소규모 보수공사 범위 — P1~P3와 같은 성격). 검색 응답의 `pbancSrchItm03` 값을 추정가격으로 쓴다 (공고 상세와 값이 같은지 C2에서 3건 대조). 추정가격 값이 없는 공고는 통과시키고 건수를 하루 요약에 적는다.
- 정정 공고(차수 > 000)는 새 공고로 다시 검토하되 알림에 "정정 공고"로 표시.
- 하루 처리 상한: **새로 등록하는 공고** 30건 (넘으면 다음 날). 2026-11-11 수정: 처음 구현은 이미 본 공고까지 30건 안에 세어 밀린 공고가 계속 밀렸음 → kdoc-api 가 새 등록 수만 세도록 고침 (`/bids`의 `daily_limit`). 규칙의 뜻은 그대로.

### 4.2 첨부 분류 규칙 (A2)

| 순서 | 조건 | 분류 |
|---|---|---|
| 1 | 확장자 `.hwp .hwpx` | unsupported (사유: HWP) |
| 2 | 파일명에 `시방` 이고 `.pdf` | spec |
| 3 | 파일명에 `내역` 또는 `설계서` 또는 `산출` 이고 `.xls .xlsx` | boq |
| 4 | 파일명에 `도면` 이고 `.pdf` | drawing |
| 5 | 파일명에 `공고` | notice |
| 6 | `.zip` | 압축 해제 후 안의 파일에 1~5 적용 (한 단계만) |
| 7 | 그 밖 | other |

시방서·내역서가 각각 1개 이상이어야 `ready`. 아니면 사유(`시방서 없음`, `내역서 없음`, `HWP만 있음` 등)를 기록하고 검토하지 않는다. **결과를 본 뒤 규칙을 고치지 않는다** — 놓친 사례는 운영 보고서에 적고 v3에서 다룬다.

### 4.3 자동 검토 설정

W1·W2의 검토는 **AI 없이**(규칙 + 이름 일치) 돈다. 같은 입력이면 같은 결과가 나오게 하기 위해서다. 사용자 짝 CSV는 자동 공고에는 없다.

### 4.4 수집 예절 (크롤링)

- 요청 간격: 검색은 키워드 사이 2초, 첨부 확인·다운로드는 1초. 하루 요청 상한 600건.
- 공고 하나당 첨부 확인은 422가 나오면 멈추고 최대 15번까지.
- 받은 원본은 sha256과 함께 저장하고 같은 공고는 다시 받지 않는다 (`seen`).
- User-Agent에 도구 이름(`kdoc-research`)을 넣는다. robots.txt(2026-11-11 확인: 구글 로봇의 게시판 경로 1개만 막음)를 따른다.
- 403·429 또는 연속 3회 실패면 그날 수집을 멈추고 W4 알림.

### 5.2 정밀도 (W3)

- 표본: P1~P3의 의심 항목 **전부** + 운영 중 검토된 공고에서 고정 시드(42)로 뽑은 5건의 의심 항목 (공고당 최대 20개, 시드로 추출).
- 판정 3단계: **진짜 문제**(두 문서 중 하나를 고치거나 질의해야 함) / **문제 아님**(표현 차이·다른 장에 있음·사전 오인) / **판단 못 함**(근거 부족).
- 정밀도 = 진짜 문제 / (진짜 문제 + 문제 아님). 판단 못 함은 따로 센다.
- `판단 불가`(공정·수치) 행은 정밀도 대상이 아니다 (도구가 이미 판정하지 않은 항목).
- 판정자는 1인(본인, 건축기사)이며 도구를 만든 사람이라는 편향을 한계로 적는다.

### 5.3 검토 시간 (D3)

- 같은 사람이 같은 문서를 두 번 보면 두 번째가 빨라지므로 **다른 공고 2건**으로 잰다: P2를 수작업 대조, P3를 보고서 보고 확인. 각각 "의심 위치 목록을 만들 때까지" 걸린 시간을 초시계로 잰다.
- 문서 분량(시방서 쪽 수, 내역서 행 수)을 같이 적고 쪽당·행당 시간도 보고한다. 1인·1회 측정이라 경향으로만 쓴다.

### 5.4 W5 (선택)

- 운영 중 10건의 초안을 "그대로 사용 / 조금 고침 / 다시 씀" 3단계로 판정. 호출 수·토큰 수 기록.

## 9. 연결 확인에서 나온 문제 (2026-11-11, C2)

- **W1 결과 (11-10~11-11 게시분)**: 새로 등록한 공고 30건 중 검토 가능 1건. 검토 못 한 사유: 시방서 없음 13 · 시방서·내역서 없음 8 · HWP만 있음 4 · 첨부 없음 4. §6 위험 2(시방서 첨부가 드묾)가 그대로 나타남.
- **검토 가능 1건도 추출 실패** (G-R26BK01808933-000 한국산업인력공단 외벽 방수공사): 시방서 35쪽에서 조항 283개는 나왔지만 비교할 장을 정하지 못함(목차가 `제1 장일반사항` 꼴, 특기시방서 구조). 내역서는 공종별내역서 124행 중 항목 7개만 추출. P1~P3에 맞춘 추출기가 새 문서 양식을 일반화하지 못한 것.
- **수정 (2026-11-11, 사용자 결정)**: 시방서에서 `제1 장` 다음 줄에 제목이 오거나 `총`/`칙`처럼 글자마다 줄이 나뉜 제목을 합치도록 고침 (`extract/spec.py`, 회귀 테스트 추가). 내역서 7개는 실제로 항목이 7개뿐인 작은 공고였음(추출 오류 아님). 이 공고를 개선 전·후 사례로 남기고, 운영 지표(D1)는 수정 뒤부터 잰다.
- '첨부 없음' 4건: 첨부 확인(fileSeq 1번)에서 바로 422 — 첨부가 다른 경로(예: 별도 시스템 링크)일 가능성. 확인 필요.
