# PLAN v1 — 시방서 ↔ 내역서 불일치 검토 (기술 계획)

작성 2026-11-03. 사업 관점은 `plan.md`. 이 문서는 무엇을 만들고 **어떻게 효과를 잴지**를 결과를 보기 전에 정해 두는 문서다.

## 1. 범위

- 1단계(이번): **시방서(PDF 텍스트) ↔ 내역서(엑셀)**. 도면은 벡터 PDF에서 뽑히는 문자만 보조 근거로.
- 제외: 도면 형상 인식, 물량 자동 산출, 구조 검토, "문제 없음" 판정.
- 스캔 도면(P2)은 OCR 대상으로 표시만 하고 2단계에서 다룬다.

## 2. 단계와 완료 기준

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| 1 추출 | 수집·PDF·엑셀 추출 | ✅ 3건 13파일 오류 0, 시방서 장 인식 7/7, pytest 통과 |
| 2 비교 | 공종 매칭 → 항목 매칭 → 속성 비교 | 아래 4가지 판정을 근거 위치와 함께 출력 |
| 3 리포트 | 엑셀 검토표 + 근거 페이지·행 + 면책 문구 | 실무자가 표만 보고 확인 위치를 찾을 수 있음 |
| 4 자동화 | n8n: 수집 주기 실행 / Webhook 업로드 → FastAPI 작업 → 알림 | 실패 시 재시도·실패 로그·알림 |
| 5 측정 | 정답 테스트셋으로 성능, 검토 시간 비교 | §4 지표 보고 |

### 비교 판정 4종 (의심 수준으로만 표기)
1. **공종 누락 의심**: 시방서에 장이 있는데 내역서에 공종이 없음 (또는 반대)
2. **항목 누락 의심**: 시방서 본문의 주요 자재·공법이 내역서 품명·규격에 없음
3. **규격 불일치 의심**: 같은 항목의 두께·재질·등급이 다름 (예: 단열재 100T vs 80T, AL vs PVC)
4. **확인 필요**: 자동으로 판단할 수 없는 경우 (근거만 제시)

### 규칙 우선, LLM은 좁게
- 공종명·두께(mm/T/THK)·재질 키워드 정규화는 규칙으로 한다 (비용 0, 재현 가능).
- LLM(gpt-5-mini)은 **표현이 다른 같은 항목 매칭**("우레탄 도막방수" ↔ "도막방수(우레탄계)")과 근거 요약에만 쓴다.
- LLM 응답은 입력 해시로 캐시한다 → 같은 문서를 다시 돌려도 호출 0회. 실행당 호출 상한(`LLM_MAX_CALLS_PER_RUN`).

## 3. 정답 테스트셋 (사전 등록)

공개 문서에는 "정답 불일치 목록"이 없으므로, **원본 사본에 불일치를 직접 심어** 정답을 만든다.

- 대상: P1·P2·P3 내역서 사본 (원본은 손대지 않음)
- 심는 유형과 개수 (프로젝트당 10개, 총 30개): 공종 삭제 2, 항목 삭제 3, 두께 변경 2, 재질 변경 2, 단위·수량 이상 1
- 심는 위치는 스크립트가 **고정 시드로 무작위 선택**하고, 정답 목록은 비교 코드를 만든 뒤에야 연다
- 원본(심지 않은 상태)에서 나온 결과는 "원래 문서에 있던 의심 항목"으로 따로 집계한다 → 사람이 직접 확인해 실제 불일치인지 분류

## 4. 지표

| 지표 | 정의 |
|---|---|
| 검출률 | 심은 불일치 30개 중 리포트에 근거 위치까지 맞게 나온 비율 |
| 오탐 수 | 원본 문서에서 나온 의심 항목 중 사람이 확인해 문제 아님으로 분류한 수 (프로젝트당) |
| 처리 시간 | 문서 투입 → 리포트 생성까지 (추출 현재 약 6초 / 3건) |
| 검토 시간 | 같은 문서 1건을 수작업으로 대조한 시간 vs 리포트를 보고 확인한 시간 (본인 측정, 방법 명시) |
| 비용 | 실행 1회 LLM 호출 수·토큰·금액 |

결과가 나온 뒤 판정 기준이나 정답을 바꾸지 않는다. 바꿔야 하면 v2로 새로 등록한다.
